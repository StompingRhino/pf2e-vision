# PF2e Vision — Proto 3: Canvas

**Идея.** ГМ выделяет токен участника боя, рядом с ним всплывает панель «Как видят <имя>»: строка на каждого другого бойца, ползунок на 5 уровней. Наведение на строку подсвечивает токен-наблюдателя, а над наблюдателями висят значки состояния цели относительно них.

## Установка
Скопировать папку в `%LOCALAPPDATA%/FoundryVTT/Data/modules/pf2e-vision-proto-3/`, включить в мире pf2e (Foundry v14, pf2e 8.1.x) вместе с `xdy-pf2e-workbench` и `pf2e-toolbelt`.

## Проверка
1. Запустить бой на сцене минимум с тремя токенами; у одного игрока должен быть свой токен в бою.
2. Под ГМ: Scene Controls, слой токенов, кнопка-глаз «Как видят цель» (включить).
3. Выделить токен-цель: рядом открывается панель (у края экрана — прижимается).
4. Подвигать ползунок у наблюдателя: Видимость / Плохая видимость / Спрятанность / Необнаруженность / Незамеченность. Под строкой подпись с чистой проверкой.
5. Навести на строку: токен-наблюдатель обводится жёлтым. Над наблюдателями со статусом отличным от «Видимость» — иконка состояния.
6. Выделить другой токен боя: панель переключается на него.
7. Под игроком (владеет токеном-наблюдателем): concealed — токен чуть прозрачен, hidden — полупрозрачен, undetected/unnoticed — токен скрыт; у concealed/hidden значок состояния. ГМ видит всё.
8. Флаг: `token.flags["pf2e-vision-proto-3"].visibility = { [observerTokenId]: state }`, отсутствие ключа = observed.

## Заглушено
- Механика бросков: чистая проверка (СЛ 5/11) и застигнут врасплох — только текст в панели, эффекты pf2e не создаются.
- Автоматика Stealth/Hide/Sneak/Seek через Workbench/Toolbelt — не подключена.
- Положение панели считается при открытии/смене цели; при панорамировании не следует за токеном.
- Если закрыть панель крестиком, кнопка в Scene Controls остаётся нажатой до перерисовки.
- Игрок с несколькими токенами: берётся самый видимый уровень; зрение по свету/стенам не учитывается.

## Чем хуже других подходов
Работа с одной целью за раз: нет обзора матрицы «все ко всем». Панель перекрывает канвас. Значки и скрытие рисуются хуком `refreshToken` на клиенте (не через переопределение `isVisible`), поэтому возможны мерцания при конфликте с другими модулями, меняющими видимость.
