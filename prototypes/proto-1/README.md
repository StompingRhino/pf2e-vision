# PF2e Vision — Proto 1: Matrix

Отдельное окно «Матрица видимости» (кнопка в шапке трекера боя, только ГМ): строки — наблюдатели, столбцы — цели, в каждой ячейке сегментный переключатель на 5 уровней.
Состояние хранится во флаге токена-цели `flags.pf2e-vision-proto-1.visibility = { [observerTokenId]: level }`, у игроков на канвасе токены тускнеют или пропадают.

## Установка
Скопировать папку в `%LOCALAPPDATA%/FoundryVTT/Data/modules/pf2e-vision-proto-1/` (имя папки = id модуля), перезапустить мир, включить модуль (нужны pf2e, xdy-pf2e-workbench, pf2e-toolbelt). Foundry 14.364, pf2e 8.1.x.

## Сценарий проверки
1. Создайте бой на сцене минимум с тремя токенами (1–2 игрока + монстр), запустите.
2. ГМ: в шапке трекера нажмите иконку таблицы — откроется матрица. Диагональ пустая.
3. В строке монстра выберите для клетки «игрок A» уровень Concealed: у игрока A (токен выбран) монстр слегка прозрачен.
4. Поставьте Hidden: полупрозрачный + значок состояния. Undetected/Unnoticed: у игрока токен исчез.
5. Направленность: уровень в строке «A -> B» не влияет на «B -> A».
6. Если у игрока несколько токенов в бою — берётся самый видимый уровень.
7. В выпадающем списке выберите уровень, нажмите стрелку вправо у наблюдателя (вся строка) или вниз у цели (весь столбец).
8. ГМ: выделите токен — на других токенах появляется значок (как их видит выделенный токен), но ГМ видит всё.
9. Сменяйте/удаляйте участников боя — окно перерисовывается.

## Заглушено
- Броски: чистая проверка (СЛ 5 / 11), застигнут врасплох через pf2e — `mechanicsStub` в `scripts/main.mjs`, пишет в консоль.
- Автоматика Stealth/Hide/Sneak/Seek через Workbench/Toolbelt — нет, зависимости только объявлены.
- Нет проверки прав/сокетов сверх того, что обновлять токены может только ГМ; есть только активный бой на текущей сцене.

## Не проверено в запущенном Foundry
Прототип писан без доступа к исходникам ядра (на машине их нет): хук `renderCombatTracker`, место вставки кнопки (`nav` шапки), хук `refreshToken` и render flags сверены только с кодом pf2e/документацией API. Первый запуск — вероятное место правок.

## Чем хуже других подходов
- Квадратичный рост: N участников = N² ячеек × 5 кнопок; при 10+ окно огромное.
- Окно отдельно от трекера и канваса: надо переключать внимание, нет контекста «что я сейчас выбрал на карте».
- Для типичного случая («один монстр спрятался от всех») нужны bulk-кнопки вместо одного клика.
